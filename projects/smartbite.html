SmartBite

A real-time restaurant ordering and billing system, built as my BSc CSIT final-year project.

Overview

SmartBite is a real-time ordering and billing application for small-to-medium restaurants. It replaces manual order tracking and paper billing with a live, cross-device system that keeps staff and the till in sync.

Role

Role: Solo developer — frontend, real-time data layer, and deployment

Problem

Manual order tracking creates bottlenecks during busy hours, and paper-based billing makes end-of-day reconciliation slow and error-prone.

Solution

Built with vanilla HTML, CSS, and JavaScript, SmartBite uses Firebase Realtime Database instead of local storage so that orders, table status, and menu changes sync live across every device watching them — no page refresh required.

My responsibilities

  • Migrated the data layer from localStorage to Firebase Realtime Database for live, cross-device sync.
  • Implemented real-time order tracking using Firebase's onValue() listeners, linking order completion to automatic table reservation release.
  • Built a firebase-ready custom event pattern to handle asynchronous initialization cleanly across ES modules.
  • Developed an admin panel with full CRUD functionality for menu items, orders, and review moderation.
  • Deployed the app on Netlify.

Outcomes

  • Live, cross-device table reservation and order status updates with no manual refresh.
  • A simpler end-of-day reconciliation process for staff, backed by real-time order and billing data.

Features

  • Live order placement and tracking
  • Real-time table reservation sync
  • Admin panel with menu and order CRUD
  • Review moderation

Technologies

JavaScript (ES Modules) HTML CSS Firebase Realtime Database Netlify

Challenges

ES modules can't run directly from the local file system, which meant setting up a local server just to test changes — a small but important lesson in how browsers handle module loading.

Lessons

Working with Firebase's async initialization taught me to design around events rather than assuming data is ready immediately — a pattern that shaped how I think about real-time systems since.
